# JuliaFlow Risk Register

Last updated: 2026-06-20

This register tracks active BRD delivery risks that should be burned down through thin, verified slices. It complements `docs/TODO.md`, `docs/brd-traceability.md`, `docs/project-tracker.md`, and `docs/checkpoint-log.md`.

## Current Risk Focus

Next implementation lane: local-first GA proof after the BRD v0.4.1 product-surface refresh. The active risk burn-down now prioritizes local appliance bootstrap, mock-aligned local product modules, local filesystem/DuckDB data estate, local PostgreSQL lab/team metadata mode, local CPU/GPU hardware validation, explainability/model evidence, offline Hub, academic reproducibility, and backup/restore. Provider-specific deployment, cloud object stores, external registries, enterprise identity, and cloud multi-GPU closure are optional compatibility paths rather than core GA blockers.

## Risk Burn-Down Order

1. Local appliance bootstrap: burn down `R-LOCAL-001`.
2. Local data estate: `R-DATA-001` is mitigated for the current managed-estate slice and replaces cloud object-store proof as the core storage gate.
3. Local metadata/database modes: `R-DB-001` is mitigated for the current metadata/database slice; backup/restore and migration integrity remain in the later backup/restore lane.
4. Local hardware runtime: `R-HW-001` is mitigated for the current hardware runtime slice; keep hardware-backed CUDA and multi-GPU evidence conditional on available local hardware.
5. Explainability/model evidence: `R-XAI-001` is mitigated for the current evidence slice; keep export/reimport depth queued for reproducibility.
6. Offline Hub: `R-OFFLINE-001` is mitigated for the current offline/local install slice; keep external registry proof optional.
7. Mock-aligned product surface: `R-PRODUCT-001` is mitigated for the current local product-depth sequence by the first frontend-shell vertical, backend-backed Data/Transform, ML Studio experiment, Models registry, Visualize checkpoint/export, Deploy package actions, and fixture-backed Playwright browser journeys across desktop/mobile local UI routes.
8. Academic reproducibility: `R-REPRO-001` is mitigated for the current export/reimport slice.
9. Backup/restore and migration: `R-BACKUP-001` is mitigated for the current appliance bundle and restore slice.
10. Mock-aligned product workflow vertical: current backend-backed local product-depth sequence and browser-gated local UI redesign are closed; future burn-down should target concrete usability gaps, not optional provider deployment.
11. AKS-5 Stage 3 lifecycle/evidence: Explorer save/run, Monitor execution records, dashboard artifact-backed rows, no-data states, and executed-run explainability evidence are implemented in the modular frontend.
12. AKS-5 Stage 5 release gate: live-backend browser QA, Docker PostgreSQL metadata smoke, and the single release-verification entrypoint are implemented and verified by full no-skip `npm run verify:release`.
13. AKS-23 project creation and shell actions: frontend slice reduces product-surface risk by replacing inert New Project/Grid/Share/Help/Profile controls with validated local-first dialogs, browser-granted target-folder scaffold file writes, and Explorer scaffold artifact evidence; a gateway-native scaffold endpoint remains optional if service-owned typed-path writes are needed later.
14. AKS-27 route resilience: current frontend slice reduces blank-screen risk by adding route-level crash containment and empty live states for Models, Deploy, Settings, shared tables, and existing Transform/Monitor/ML/Visualize paths.
15. AKS-24 Explorer system health and artifacts: first slice reduces product-surface risk with live health polling, stale-state handling, project trust evidence, and grouped artifact actions; second slice must close compute settings persistence/runtime propagation before AKS-24 closure.
16. Frontend/module depth and runtime policy: continue `R-FE-001` and `R-RUNTIME-001` only when they serve the local-first workflow.
17. Control-doc drift guard: keep `R-DOC-001` mitigated by running `npm run validate:control-doc-sync` before completion claims.
