# JuliaFlow Risk Register

Last updated: 2026-07-30

This register tracks active BRD delivery risks that should be burned down through thin, verified slices. It complements `docs/TODO.md`, `docs/brd-traceability.md`, `docs/project-tracker.md`, and `docs/checkpoint-log.md`.

## Current Risk Focus

Next implementation lane: local-first GA proof after the BRD v0.4.1 product-surface refresh. The active risk burn-down now prioritizes local appliance bootstrap, mock-aligned local product modules, local filesystem/DuckDB data estate, local PostgreSQL lab/team metadata mode, local CPU/GPU hardware validation, explainability/model evidence, offline Hub, academic reproducibility, and backup/restore. Provider-specific deployment, cloud object stores, external registries, enterprise identity, and cloud multi-GPU closure are optional compatibility paths rather than core GA blockers.

### AKS-36 RC Closeout And Evidence-Binding Risk Note - 2026-07-30

- Bounded RC implementation is complete on draft PR #40; product/API/runtime
  feature expansion is not part of this closeout.
- Pull-request CI now defines a full Debian `verify:release` job against the PR
  head SHA. Release summaries bind commit SHA, tree SHA, platform, and
  clean-worktree state, and a no-skip candidate fails closed when dirty.
- Exact-head Windows verification exposed an Application Control block on a
  newly precompiled `LibGit2_jll` depot DLL. The local smoke dependency
  bootstrap and smoke gateway now run with compiled modules disabled, matching
  the existing release Julia phases without weakening product assertions. Cold
  single-user smoke readiness is bounded at 60 seconds; lab-team remains
  bounded at 90 seconds.
- Metadata repository probes preserve the configured read-only depot fallback
  and use compiled-modules-disabled mode, retaining fail-closed file and
  PostgreSQL assertions for the exact candidate environment.
- Residual delivery risk is exact-head Windows and hosted Debian evidence,
  structured domain review and finding disposition, required checks, merge,
  post-merge RC metadata, tag workflow, prerelease publication, final evidence
  reconciliation, and Linear readback.
- GitHub-hosted jobs at the prior head failed before steps because the owner
  account billing/spending limit prevented runner startup. This is an external
  delivery blocker, not regression evidence, and it also provides no Debian
  parity.
- Database, watched-folder, USB, cloud/provider connector support and successful
  CUDA execution remain outside the RC claim boundary.

### AKS-36 Hyperparameter-Grid Risk Note - 2026-07-03

- Local CSV validation-only tuning now searches feature-set plus hyperparameter variants when `maxTrials` allows it.
- Regression trials record regularization-strength variants; binary-classifier trials record classification-threshold variants while preserving probability-ranked AUC.
- Remaining risk: this is still native local CSV tuning, not MLJ package-backed optimization or actual GPU-accelerated trial execution.

### AKS-36 MLJ-Compatible Model Evidence Risk Note - 2026-07-04

- MLJ-prefixed training/tuning requests now carry model-family, package-availability, generated Julia code, and explicit local fallback evidence.
- Final evaluation, prediction scoring, registry evidence, and deploy runtime selection preserve requested MLJ-compatible model metadata while scoring via the supported `nativeModelKind`.
- MLJ package availability/version detection, explicit `JULIAFLOW_ENABLE_MLJ_PACKAGE_FIT` opt-in, bounded package-backed model-family support, route-wiring status, and `mljPackageFitExecuted` are now recorded separately; requested MLJ paths continue to record `localFallbackUsed=true` until package-backed fitting is actually wired and verified.
- Remaining risk: this predated the dependency-backed and persisted-machine proof; broader tuning, richer preprocessing, broader drift semantics, and actual GPU-accelerated trial execution remain open.

### AKS-36 Readiness/Wizard/Accessibility Risk Note - 2026-07-08

- The implementation-readiness review now distinguishes accepted AKS-36 substrate evidence from remaining blockers in contract/API, security, ML validity, MLOps lifecycle, and frontend/persona review.

Folder grants, deeper connector-specific redaction review, broader gateway extraction, richer MLJ preprocessing/tuning/drift semantics, compatible GPU evidence, and final child-ticket traceability remain open.

- The full Julia suite is confirmed slow rather than hung: the API Gateway top-level testset dominates local runtime.
- API Gateway CORS mutation tests now use a fresh execution id so allowed-origin mutation coverage does not invalidate later transition-status assertions.

- Remaining risk: the suite is still monolithic, so future API Gateway work should split scenarios into independent fixtures while preserving the current pass/fail/error coverage.

### AKS-36 MLJ Route-Wired Fit Risk Note - 2026-07-09

- Supported MLJ LinearRegressor/LogisticClassifier-style requests now have a route-wired package-fit hook when MLJ/MLJLinearModels are discoverable and `JULIAFLOW_ENABLE_MLJ_PACKAGE_FIT=true`.
- Training and validation-only tuning pass train-scope feature/target rows into the MLJ evidence helper, which dynamically imports MLJ only for route-wired requests and records runtime import, fit failure, or fit-executed evidence.
- Deterministic local CSV artifacts remain the explicit fallback whenever package-backed fitting does not complete, so package discovery or opt-in cannot be mistaken for a successful MLJ fit.
- Final-evaluation model runtime evidence, including `mljEvidence`, is now propagated into prediction-export validation evidence and local drift evidence so package-fit/runtime status remains visible through evaluation, export, and monitoring records.
- MLJ and MLJLinearModels are now project dependencies for the bounded local proof. Focused Julia helper coverage verifies explicit package-backed local CPU fit/scoring for `MLJ.LinearRegressor` and `MLJ.LogisticClassifier`; classifier targets are coerced to MLJ finite targets before fitting.
- Final evaluation, prediction export, and drift now have a bounded package-backed scoring path that refits the MLJ model from train-scope rows and scores requested rows, recording `mlj_package_backed_final_evaluation`, `mlj_package_backed_prediction_export`, and `mlj_package_backed_prediction_distribution` evidence when successful.
- Remaining risk: persisted MLJ machine artifacts and bounded deploy-runtime serving are implemented. Hardware-gated CUDA validation-metric execution is also implemented with explicit CPU fallback, but the current CUDA 13.3/CUDA.jl 13.2 mismatch prevents successful local GPU evidence; richer preprocessing/tuned GPU fitting and broader drift semantics remain before readiness claims.
