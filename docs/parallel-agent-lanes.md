# JuliaFlow Parallel Agent Lane Guide

## Goal

This document expands `docs/parallel-lanes.md` into implementation-ready ownership and handoff rules. It defines who owns what after contract freeze so parallel Codex agents can work with low merge risk. It assumes concurrent contributors exist and forbids ad hoc edits across lane boundaries.

## Serial Gate Before Parallel Work

Only one lead thread should edit shared contracts before `cp/01-contracts-frozen`:

- `packages/contracts/`
- repo-level workflow/API/protocol versioning
- checkpoint rules in `docs/checkpoints.md`
- ADRs that change architecture direction

Docs and infra docs can move in parallel with lead thread if they do not redefine contract behavior.

## Lane Ownership

| Lane | Scope | Primary Paths | Starts After | Must Not Edit |
| --- | --- | --- | --- | --- |
| Lead / Contracts | Schema, protocol, checkpoint policy, interface freeze | `packages/contracts/`, `docs/adr/`, `docs/checkpoints.md` | Immediately | feature lane internals unless coordinating freeze |
| A Frontend | Canvas UI, node search, configuration panels, dashboard UX | `apps/frontend/`, `packages/ui/` | `cp/01-contracts-frozen` | Julia services, shared contracts without lead approval |
| B API Gateway | REST handlers, JSON-RPC session layer, auth middleware | `services/api-gateway/` | `cp/01-contracts-frozen` | frontend app state, execution internals, contract files |
| C Execution Core | DAG planner, workflow runtime, Redis/Kafka wiring, checkpoints | `services/execution-service/` | `cp/01-contracts-frozen` | frontend paths, API-only concerns, contract files |
| D Node SDK / Extensions | Node lifecycle, official packs, extension manifests | `services/node-sdk/`, `extensions/` | `cp/01-contracts-frozen` | gateway/frontend paths, contract files without freeze review |
| E Streaming Runtime | stream adapters, backpressure, recovery, replay | `services/execution-service/` subpaths reserved by owner | `cp/03-alpha-gpu-bi` | gateway/frontend unless interface ticket exists |
| F BI Layer | semantic layer, dashboard query path, live updates | `apps/frontend/` BI area plus future BI service path | BI outlet contract freeze | node SDK internals, unrelated runtime code |

## Parallelization Map By Checkpoint

### `cp/00-foundation` to `cp/01-contracts-frozen`

- Safe parallel lanes: Lead / Contracts, H Infra / DevEx, Docs / Release Ops
- Unsafe parallel work: frontend features that need unstable contracts, runtime features that invent new payload shapes

### `cp/01-contracts-frozen` to `cp/02-alpha-core`

- Safe parallel lanes: A, B, C, D, H, Docs
- Merge cadence: contract changes only on dedicated freeze branch; feature lanes consume versioned contract update after merge

### `cp/03-alpha-gpu-bi` onward

- Additional parallel lanes: E Streaming, F BI, G Hub
- Requirement: event schemas, BI outlet metadata, extension manifest format must already be versioned

## Concurrent Edit Rules

- One lane, one path owner. If work spans multiple owners, create integration branch after both owners merge independently.
- Shared contract files require explicit freeze note in ADR or release note before merge.
- Generated artifacts should be regenerated by owner lane only. Do not hand-edit generated client/protocol output in unrelated lane.
- Rebase often. Never revert unknown changes from other contributors. Adapt docs and scaffolding to latest repo state.
- Large milestone merges should land near checkpoint tags, not mid-freeze.

## Handoff Requirements

Every lane handoff should include:

- touched paths
- contract version consumed
- tests run
- open risks and next owner
- checkpoint target (`cp/*`)

## Checkpoint Ownership

Use these checkpoint leads:

- `cp/00-foundation`: Lead / Contracts + H + Docs
- `cp/01-contracts-frozen`: Lead / Contracts
- `cp/02-alpha-core`: A + B + C + D coordinated by Lead
- `cp/03-alpha-gpu-bi`: C + D + F
- `cp/04-beta-streaming`: C + E
- `cp/05-beta-security-hub`: B + G + H
- `cp/06+`: cross-lane release train with checkpoint note in `docs/releases/`
