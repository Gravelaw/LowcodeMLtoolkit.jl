# AKS-58 M2 hardware evidence record

## Scope and decision

This draft implements an additive v2 resource-evidence contract and repairs false GPU execution claims. A registry string is always simulated. `nvidia-smi` inventory establishes visibility only; a device becomes usable only after CUDA.jl binds it, allocates an array, performs an operation, synchronizes, reads the expected result, and confirms the output device. Gateway health exposes CUDA package installation, visible devices and usable devices separately. Project jobs that still fit/profile/evaluate on CPU report CPU as the actual backend; their routes reject `cuda_required` before CPU work or artifact writes. The supported worker affine operation binds its selected physical device before allocation; required GPU rejects absent or unmatched hardware, while preferred execution can report an explicit CPU fallback. Mock workloads report CPU execution.

Historical records without `evidenceVersion` remain historical, with no inferred GPU success. Gateway repository mappings round-trip the new worker fields; project evidence uses `evidenceVersion: 2`. The frontend is unchanged.

## Evidence and limits

At the Windows host, `nvidia-smi` reports an RTX 5080 Laptop GPU with UUID `GPU-c794920c-cf75-61f2-cf43-fe36b87f11d5`, 16,303 MiB reported memory, and driver 616.92. An inventory-only run of `node scripts/run-julia.mjs --project=. scripts/smoke-hardware-evidence.jl` with `JULIAFLOW_DISABLE_HARDWARE_PROBE=1` reports one visible, zero usable, probe skipped. It measured 16 CPU threads, 33,752,915,968 total RAM bytes and 1,466,554,286,080 free disk bytes at that instant. The first required physical probe failed; an artifact download reported corruption before retry, and CUDA.jl warned that it was precompiled for CUDA 13.2 while runtime CUDA was 13.4. The failure was traced to a Julia world-age error after dynamic CUDA loading. After repairing that call boundary, `JULIAFLOW_REQUIRE_CUDA_PROBE=1` passed: one visible/usable device, allocation/operation/synchronization/readback, and the selected UUID matched the actual output device. The separate worker affine operation returned `[3, 5, 7, 9]` (sum 24) on the same UUID with CUDA backend. CUDA.jl still emits the 13.2/13.4 warning; this bounded success does not qualify every workflow or platform.

The worker slice passed 55 job-helper and 216 worker assertions after the per-device failure-status refinement. The project-contract slice passed 13 core, 55 job-helper and 279 payload assertions. The repository slice passed 53 assertions with one existing broken PostgreSQL integration case, plus 279 payload assertions. The helper slice passed 558 assertions. The separate realtime slice passed 74 API realtime and five cleanup assertions, including required-GPU failure. The full local API gateway slice passed 1,078 gateway, 37 browser-boundary, 261 project-evidence, and 122 split-membership assertions. `npm run validate:contracts` passed 63 assertions with three platform skips. The first `npm run smoke:local-hardware` passed its isolated single-user CPU path; CUDA smoke and the physical operation probe were skipped with `not_requested`. These are local Windows results on Julia 1.13.0 from the repository launcher; the mapped WSL Julia 1.12.7 and full release profiles remain separate. Full worker and WSL hardware qualification remain open.

An opt-in `JULIAFLOW_CUDA_SMOKE=1 npm run julia:test:worker` run of the full test process failed twice: 216 ordinary worker assertions passed, but the newly added physical probe assertions observed `no_usable_cuda_device`. The underlying CUDA operation raised GPUCompiler `InvalidIRError` with `gpu_gc_pool_alloc` and dynamic function invocation errors during kernel compilation. The opt-in assertions remain in the test suite and must pass before a full worker GPU execution claim. The standalone probe/operation success above is narrower.

`JULIAFLOW_CUDA_SMOKE=1 npm run smoke:local-hardware` passed the single-user local gateway smoke and its separate required physical probe process. The reported device count was one, the operation sum was 24, and selected and actual GPU UUIDs matched. Its `smoke-cuda-kernel.jl` subcheck deliberately ran with CUDA smoke disabled and reported a skip; it is not counted as an additional GPU pass.

In the mapped Ubuntu WSL distro, Julia reports 1.12.7 and `nvidia-smi` reports the same GPU UUID. That establishes visibility only; the WSL Julia project/dependency profile and physical operation were not run.
