# AKS-58 M2 hardware evidence record

## Scope and decision

This draft implements an additive v2 resource-evidence contract and repairs false GPU execution claims. A registry string is always simulated. `nvidia-smi` inventory establishes visibility only; a device becomes usable only after CUDA.jl binds it, allocates an array, performs an operation, synchronizes, reads the expected result, and confirms the output device. Gateway health exposes CUDA package installation, visible devices and usable devices separately. Project jobs that still fit/profile/evaluate on CPU report CPU as the actual backend; their routes reject `cuda_required` before CPU work or artifact writes. The supported worker affine operation binds its selected physical device before allocation; required GPU rejects absent or unmatched hardware, while preferred execution can report an explicit CPU fallback. Mock workloads report CPU execution.

Historical records without `evidenceVersion` remain historical, with no inferred GPU success. Gateway repository mappings round-trip the new worker fields; project evidence uses `evidenceVersion: 2`. The frontend is unchanged.

## Evidence and limits

At the Windows host, `nvidia-smi` reports an RTX 5080 Laptop GPU with UUID `GPU-c794920c-cf75-61f2-cf43-fe36b87f11d5`, 16,303 MiB reported memory, and driver 616.92. An inventory-only run of `node scripts/run-julia.mjs --project=. scripts/smoke-hardware-evidence.jl` with `JULIAFLOW_DISABLE_HARDWARE_PROBE=1` reports one visible, zero usable, probe skipped; this is not GPU qualification. It measured 16 CPU threads, 33,752,915,968 total RAM bytes and 1,466,554,286,080 free disk bytes at that instant. The first required physical probe failed while CUDA.jl was precompiled for CUDA 13.2 and the local runtime was CUDA 13.4; a CUDA runtime artifact download also reported corruption before retry. Its final status was failed with no usable device. Preserve the mismatch as an environment failure, not a CUDA success.

The worker slice passed 55 job-helper and 216 worker assertions after the per-device failure-status refinement. The project-contract slice passed 13 core, 55 job-helper and 279 payload assertions. The repository slice passed 53 assertions with one existing broken PostgreSQL integration case, plus 279 payload assertions. The helper slice passed 558 assertions. The separate realtime slice passed 74 API realtime and five cleanup assertions, including required-GPU failure. `npm run validate:contracts` passed 63 assertions with three platform skips. `npm run smoke:local-hardware` passed its isolated single-user CPU path; CUDA smoke and the physical operation probe were skipped with `not_requested`. These are local Windows results on Julia 1.13.0 from the repository launcher; the mapped WSL Julia 1.12.7 and full release profiles remain separate. The API, real-device, and WSL results must be added only after their runs finish.

M2 remains open. The current work does not establish successful physical NVIDIA operation, all CPU/RAM/disk/VRAM pressure rejection cases, other-vendor detection and qualification, full project job GPU fitting, Windows/Debian parity, required checks at the final code head, submitted review, or merge. AKS-59 and later stages must not infer broad acceleration from this one operation path.
